# 平台身份池模型规范


## 分层与结构

Core 提供结构校验、查找、引用、原子存储、快照冲突和脱敏。Pack 声明角色用途、必需场景、关系与密码策略；Adapter 核验真实登录及业务前置条件。Core 不根据字段名、OAS、角色名字或 Java 类型猜业务线型、身份关系或可写对象。

`version` 当前为整数 1；历史文件缺少版本或空集合时按 v1 补齐，未知版本拒绝读取与覆写，须显式迁移。所有集合是对象数组，所有记录的 `id` 是稳定、全池唯一的非空字符串；`scenarios` / `fixtures` 的 `name` 在并集中唯一。JSON 重复对象键、NaN、Infinity、非 JSON 值与隐式对象键转换均拒绝。

| 记录 | 必须满足 | 可选业务字段 |
| --- | --- | --- |
| identities | category 为 Pack 显式声明的合法类别；有效 role 或 roles；roles 不重复；stages 为阶段名称到对象的映射 | 扩展字段原样保存合法 JSON，业务类型由 Pack / Adapter 按契约验证；Core 不按字段名字猜类型 |
| scenarios | 稳定 id 与唯一 name；data / identity_refs 是对象 | refs 的每个成员必须引用池内身份 id，支持单个字符串或不重复的字符串数组 |
| fixtures | 稳定 id 与唯一 name；data 是对象 | 负向参数保持原 JSON 类型；不得引用登录身份 |

顶层身份、场景、夹具的 `status` 表示平台可用状态：缺省或 active 可用，disabled / inactive / deleted 不参与运行查找。available、used、closed 等流程阶段状态放在 `stages.<stage>`，不能混用。面板仍展示停用记录及其状态，但将引用它的必需角色/场景标缺；审计与运行时使用同一判定。

`data` 中的 ID、金额、日期等原始 JSON 值在读写中保持原类型。请求、响应和 DB 转换由所属 Pack / Adapter 按证据执行，不能因身份池支持字符串和整数就放宽接口响应断言。

## 查询与执行

- `get_identity(category, role)`：唯一显式主角色优先于别名；同一优先级多个候选时报 IdentityUnavailable，不取首条。通用分组角色可出现在多个记录中，需要执行的角色必须唯一，或改用场景中的稳定身份引用。
- `find_identity(...)`：所有非空条件必须同时命中同一个身份；无条件不返回任意身份；user / agent 同登录名的双记录需要限定 category 或身份 id。工作流兼容视图遵循同样的多条件约束。
- `scenario_identity(name, alias)` 只返回一个成员；多个成员用 `scenario_identities`。禁止单成员 API 默默取列表第一项。引用停用/不存在身份不作为可用样本。
- `ensure_scenario_ready` 核对 Pack 声明的字段、引用及最长前缀元信息，和面板、审计一致。缺少、歧义或关系不满足时返回明确 incomplete；结构损坏作为模型错误报告。不能把原 runner 中的 ok=True / incomplete 当作通过，应使用平台归一化结果。
- `identity_requirements.distinct_roles` 的 category、role、other_role、fields、unique 是显式关系约束；运行时、面板与审计同时执行，不只在展示层提示。

写接口的逐例开关在身份/场景读取、登录和 DB 操作之前检查。缺少样本的 runner 使用已有 incomplete 分支，原始 HTTP、原始 JSON 类型、写前/写后状态及恢复失败断言继续保留。

## 存储与并发

`load_pool` 返回带私有源码签名的字典快照，签名不进入 JSON / 面板输出。`save_pool(snapshot)` 拒绝过期或其他池的快照；遇到 PoolConflict 重新读取并重做修改，不能把快照转成普通 dict 来绕过检查。完整普通 dict 写入仅用于显式初始化或经过审阅的迁移。

增量修改使用 `update_pool(mutator)` / upsert API。读、修改、校验、写入在同一线程锁和文件锁内完成，面板与本机 CLI 共用锁。文件锁采用当前 POSIX 运行环境的 fcntl。写入临时文件采用 0600、flush / fsync，再原子替换；校验或替换失败不改变原文件，临时文件清理。未知模型版本不自动改成 v1。




## 回归与维护

接口案例测试使用临时的合成池，显式创建所需身份、场景和夹具，不使用本机真实池或废弃环境变量。缺失、冲突、停用、HTTP 404 冒充 401、意外状态变更和恢复均应保留断言。只执行受影响的定向测试，禁止用全量业务案例代替模型验证。

面板结果中的 historySaved / historyError / runId 表示运行历史保存情况，与案例 passed / failed / incomplete 分开；保存失败在日志、API 和结果区可见，不能重执行业务 runner 来补历史。


## 可选资源能力

`resource_pool` 未声明且没有身份类别要求时，资源池关闭，面板不展示入口或读取池文件。显式关闭使用 `{"resource_pool":{"enabled":false}}`。

启用时由 Pack 声明 `title`、`description` 和 `categories`；每项提供 `id`、`label`、`storage`（identities/scenarios/fixtures）与可选 `display_fields`。例如设备类别可声明为 `{"id":"device","label":"测试设备","storage":"identities"}`。类别不限定为用户、代理或管理员；未声明的类别不可登记。场景和夹具也只有声明后才展示。
