# 第一次使用 TestDock

Core 是通用执行平台；Pack 保存一个项目的案例、资源和规则；Adapter 负责它的认证、HTTP 和响应解析。一个进程只加载一个 Pack；两个项目使用不同端口、配置和数据目录。

1. 按根目录 README 启动 demo，打开面板，在“离线只读样例”中运行 DEMO-R01。它只读取合成 mock，不调用真实业务。
2. 结果有四态：passed 是断言通过，failed 是确实失败，skipped 是明确排除，incomplete 是缺配置、资源或未完成。后两者都不算通过。
3. SAFE 是登记的只读范围；LIVE 可能写入业务环境。LIVE 需要启动配置 `PLATFORM_ALLOW_LIVE=1`、页面确认和服务端 `confirmLive`；Pack 的逐例写入开关仍需独立满足。
4. 接入自己的项目，运行 README 中的骨架生成与验证命令。新离线骨架案例 ID 为 SAMPLE_APP-R01，登录、协议和断言再按已确认的证据替换。不要猜真实字段。
5. 修改后运行 `bash scripts/check.sh`，仅执行变更相关的离线回归。Mock 通过不能代替真实业务只读验收。

## 升级前保留项目资产

先以发行工具分别导出 Core 与指定 Pack，保存各自收据、私有环境文件和运行数据。私有配置、账号池和历史不会自动进入发行包。把 Pack 发行包的相对目录安装到新的 Core 副本，核对 Pack 的 platform_api 版本门禁，再按操作手册依次完成体检、mock、定向回归和授权真实只读验收。不得直接覆盖正在运行的 checkout 或绕过版本门禁。

当前 Pack 安装位置仍在平台目录内；外部目录直接装载尚未实现。升级、回滚与运行中契约切换都应使用独立副本，不把手工文件复制当作原子激活。
