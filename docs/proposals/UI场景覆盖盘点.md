# 统一 UI 规范的场景覆盖盘点

**2026-11-18 · 对照 v0.1 与 v0.2 · 静态盘点**

两个工作台的前端入口归并为 **64 类交互**。原草案可以完整指导其中 **8 类（12.5%）**，另有 **27 类（42.2%）** 已提到原则但需要补规则，**29 类（45.3%）** 没有对应场景。至少涉及一部分的合计为 **35/64（54.7%）**。新版给全部 64 类写明了默认行为、可定制项和可观察的验收样例。 [可随平台发行的 v0.2 规范](../guides/统一UI场景规范.md) · [v0.1 草案](TestDock统一UI规范草案.md)

## 数字怎么读

- 分母为本次源代码清单中的**交互类型**。同一模式在多个页面、多个订单、多个用例或多个业务枚举中出现，按一种计数。若状态不同会改变用户下一步、确认对象或证据要求，则另列，例如“上传付款凭证”和“复核批次回执”。
- “完整”表示 v0.1 正文已有该场景的核心呈现、异常或边界行为以及可判断结果的验收方法。“部分”表示已有通用条款但开发者仍需决定一个关键分支。“缺失”表示没有该交互的专门规则。对照 v0.1 正文和验收表，链接出去的组件能力不自动计入原草案。各行均为人工分类，可逐条复核。
- 来源包括业务 Pack 主面板、通用工作台与诊断标签、动态构造的工作区、条件按钮、独立页、HTML 生成器、保留模板与示例。管理端仅引用库内既有走查所列场景，未把另一套产品所有后台功能纳入分母。纯后端接口和自动案例仅在有前端交互时计入。归并时保留原分支，历史报告的通过数不计入本轮统计。

## 入口清单

样本一主页面来自 `packs/<项目 Pack>/panel.html`，`routeHash` 和 `parseHash` 对应 home、cases、data、client、guess、bonus、agent、fiatpay、trackload、pools、guide 共 11 个顶层视图。套件内条件区及洞察八标签分别盘点。样本一保留本地既有数据与报告，管理端走查为工作区旁证。独立字典与交易报告生成器也纳入展示类场景。

样本二以 `packs/mc_pay/current/panel.py` 和已注册的 `ui/cases.html` 为入口。工具名称以 `ui/tools.js` 的 11 个键核对。两类基线客户端按需加载 HTML 片段。收银台、模拟器和网关生成的页面另列。保留版 `ui/workbench.html`、通用后备页和示例只作为组件来源。旧 URL 跳到现用入口后按同一场景计数。
