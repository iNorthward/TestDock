# TestDock 统一 UI 规范草案

**v0.1 · 2026-11-18 · 首版存档**

新接入项目优先使用 v0.2，可逐场景采用默认方案或由 Pack 定制。此处保留首版正文，供复核覆盖率与设计演进。 [统一 UI 场景规范 v0.2](../guides/统一UI场景规范.md) · [场景覆盖盘点](UI场景覆盖盘点.md)

适用于 TestDock 通用工作台和接入工作台的自定义 Pack 页面。正文中的“必须”是拟议的验收条件，“默认”是新页面可直接采用的设计值。现有页面在修改相应组件时逐步对齐。

## 1. 从两个“开启”按钮说起

同一页有 A、B 两个独立服务。用户点击 A 的“开启”后，应该立即看到 A 变为“启动中…”，B 仍可操作。若服务已经启动但响应丢失，A 应显示“结果待确认”，给出“查询状态”。查询确认后才显示“已启动”，并开放“关闭”。按下按钮、请求已受理、服务已启动，这三个时刻分别有各自的证据。

这个例子引出了两条分工。**平台统一用户如何识别动作、进度、结果，以及如何恢复。Pack 定义动作影响哪个对象、与哪些操作冲突，以及哪些业务事实足以确认结果。** 后面的视觉与交互要求适用于新建或修改的页面。Pack 可选用现成组件，也可用自己的布局实现同样可观察的行为。

## 2. 样式和组件归属

| 范围 | 必须统一 | Pack 可以决定 |
|---|---|---|
| 主题与颜色 | 工作台页面跟随根节点 `data-theme`。背景、面板、文字、次要文字、分隔线、强调色分别取 `--bg`、`--panel`、`--txt`、`--mut`、`--line`、`--acc`。成功、待确认、错误使用主题语义色与可读文字。四个可见主题均应可读，独立打开的弹框也要继承主题。 | 品牌图标、图表分类色和业务枚举名称。扩展色限定在 Pack 根节点，提供各主题下的可辨表示。 |
| 字体与层级 | 正文、标题、代码与原始值分别使用已有字体变量 `--font-body`、`--font-display`、`--font-mono`。同角色使用同一级字号。错误、状态和按钮文字在窄屏仍可读。 | 页面标题、列名、内容分组和信息密度。长编号可换行或局部滚动，并提供查看完整值的途径。 |
| 尺寸与间距 | 同一操作组的同级按钮等高，图标、文字、忙碌标识对齐。状态改变时保持布局稳定。优先使用现有 `--radius-*` 和共享按钮样式。 | 采用标准或紧凑密度。紧凑表格、图标按钮可以缩小外观，同时保留可用点击区和可访问名称。 |
| 外壳与导航 | 使用共享外壳的页面沿用分组侧栏、工作标签、当前项、关闭和主题持久化行为。链接负责导航，按钮执行动作，筛选或切换控件显式标明当前选择。 | 业务入口、分组顺序、默认视图，以及自定义 `panel_html` 的内部布局。仅展示本 Pack 声明的能力。 |
| 操作与反馈 | 主操作、普通操作、危险操作有一致的视觉层级。处理中、成功、失败、结果待确认均有文字，反馈贴近本次操作的对象。键盘激活和指针点击进入同一处理流程。 | 动词、业务成功条件、互斥范围、权限、前置条件与确认文案。危险写操作沿用项目已定义的确认和授权流程。 |
| 表单、列表、弹框 | 输入有标签，字段错误就近显示并保留输入。列表区分加载、空结果、读取失败和已加载。超宽表格在容器内横滚。弹框有标题、可见关闭按钮、Esc 关闭、Tab 焦点循环，关闭后焦点返回触发控件。 | 字段与详情白名单、排序、分页、表单恢复范围、单位、有效精度和显示时区。 |

**新页面的默认尺寸（提案）**。页标题 24–26 px，区段标题 16–18 px，正文和普通操作 14 px，辅助文字 12 px。控件内部间距 4 或 8 px，同组间距 8 px，区块间距 16 或 24 px。普通按钮最小高度 34 px，触屏独立操作优先提供 44 px 点击区。按钮圆角取 `--radius-md`（8 px），面板取 `--radius-lg`（12 px）。断点随内容决定，以窄屏能否读清、点击和恢复任务为验收依据。

目前 TestDock 提供 Claude（默认）、暗色控制台、文档工作台、工程控制台四个可见主题，已有本地字体、圆角变量、共享外壳及交互组件。部分共享反馈仍使用固定色值，详情弹框仍有固定白底。上面的尺寸档位、跨主题反馈和统一按压效果属于本草案提出的对齐项。 [主题注册](../../assets/theme-switcher.js) · [主题基础样式](../../assets/themes/base.css) · [工作台组件样式](../../assets/workbench-components.css) · [Pack 接入手册](../onboarding/AGENT_INTEGRATION.md)

落地时，共享颜色和尺寸放在主题或基础样式中，通用按钮、提示和弹框行为归共享组件，工作标签与侧栏归工作区外壳。Pack 的 CSS 以自己的页面或组件为作用域，避免全局选择器改写其他平台控件。第一批可选共享执行按钮、一组同页独立操作和一个含表格的详情弹框，用这三个入口校准后再按清单扩展。 [工作区外壳](../../assets/workspace-shell.css) · [交互组件实现](../../assets/workbench-components.js)

## 3. 按钮反馈与异步动作

先判断用户做的是什么，再决定需要哪些状态。展开、切换标签和本地筛选立即更新内容，同时更新展开或选中语义。复制在按钮旁显示“已复制”或具体失败原因。读请求支持重新读取。会产生业务副作用的操作遵循下表。

| 阶段 | 页面必须给出的反馈 | 何时允许下一步 |
|---|---|---|
| 可操作 / 有前置条件 | 使用“保存设置”“查询状态”等具体动词。因条件不足而禁用时，在附近写明缺什么及如何满足。图标按钮有可访问名称，键盘焦点清晰可见。 | 前置条件满足后启用。已禁用的控件阻止鼠标、键盘和表单回车重复触发。 |
| 已按下 | 普通动作按钮默认轻微缩至 97.5%，松开恢复，回弹约 160 ms。键盘保留焦点环，触屏无需悬停提示。减少动态效果时去掉缩放和旋转，保留背景或边框变化及状态文字。导航、整行链接和禁用按钮保留自身反馈。 | 按压只表示收到了输入。只处理一次激活，不为展示动画而延迟执行。 |
| 已提交 / 处理中 | 发请求前同步拦截重复触发，按钮改为动作进行时并标记 `aria-busy="true"`。限制同一对象的冲突操作，独立对象仍可用。需要整组锁定时，给出组级进度和锁定原因。 | 同一逻辑操作只提交一次，业务幂等由 Pack 契约保障。结束后清除忙碌标识，根据最新业务状态重算可用性，保留原有权限和禁用条件。 |
| 结果已确认 | 在原按钮、行或卡片附近显示具体结果，更新对应对象，再给出下一步动作。任务回执仅能支持“已受理”，任务终态和业务成功分别判定。 | 由 Pack 根据该动作的契约和返回证据决定是否可继续。 |
| 明确失败 | 展示原因和可行的修正动作。保留用户输入与上次已确认的结果，说明后者的时间或状态。区分字段校验、权限受限、业务拒绝。 | 仅在业务允许且原因可处理时开放重新提交。 |
| 写入结果未知 / 恢复查询 | 超时、断线、响应不可判读且无法确认是否生效时，显示“结果待确认”。入口改为“查询原操作”或“核验状态”。查询再次失败，保留原标识、已知事实和查询入口。 | 用原请求号、任务号或 Pack 声明的只读途径核对。刷新、重新打开详情、恢复查询均不自动重发写操作。无可用查询途径时给出人工核验指引。 |

局部提示优先复用 `PlatformWorkbench.feedback`。使用 `info / success / warning / error`，由 `role=status` 和 `aria-live=polite` 播报。加载后仍需处理的错误或待确认状态保留在当前对象旁。若同时展示全局摘要，摘要指向对应对象。切换对象后，旧响应不能清除新对象的提示或覆盖其结果。

对于已接入共享执行客户端的任务，首次响应丢失时可按原 `requestId` 与 `kind` 查询回执，取得 `executionId` 后查询原任务。刷新时从对应 Pack、页面和作用域恢复。结果过期或缺少执行证据时沿用 `ok: null, status: "incomplete"`。普通业务动作由 Pack 提供查询途径和成功判据。 [工作台交互组件](../guides/工作台交互组件.md) · [执行客户端](../../assets/execution-client.js) · [平台与项目隔离规范](../architecture/平台与项目隔离规范.md)

## 4. 按改动范围验收

| 改动 | 选测入口 | 浏览器中须观察的结果 |
|---|---|---|
| 主题、字体、圆角、按钮外观 | `node --test tests/test_theme_contract.js` 检查主题选择与持久化。在受影响的实际页面补验样式。 | 四个可见主题各检查同一组代表控件。用鼠标按住再松开、用键盘聚焦并激活，检查普通、禁用、忙碌状态和减少动态效果。记录异常主题及具体状态。 |
| 共享反馈、弹框、列表、复制 | `node --test tests/test_workbench_components.js`，再用下述双 Pack 浏览器脚本验证已有组件。 | 在 1280×900 与 390×844 检查反馈归属、Esc 和焦点返回、表格局部横滚、长错误可读。另在本次实际改动页面检查 CSS 覆盖与动态行按钮。 |
| 共享执行、请求去重、任务恢复或跨组件联动 | `PLATFORM_ENV_FILE=/dev/null python3 scripts/targeted_regression.py --group execution-ui --plan` 预览，移除 `--plan` 后执行该组。 | 在合成环境触发慢响应、双击、明确拒绝、已受理但响应丢失、刷新及连续两次查询。记录每一步的写入次数、查询次数和原操作标识。 |
| 单个 Pack 的页面或业务动作 | 按该 Pack 注册的定向组或受影响测试文件选测。共享组件有改动时叠加对应项。 | 覆盖每种改动动作的全部入口和有意义的异常分支。对 A 操作期间激活独立 B，再切换对象使 A 的旧响应迟到，检查锁定范围与结果归属。涉及真实业务结论时，另用获授权环境和可核对的业务证据验收。 |

**双 Pack 浏览器验收**。使用仓库已有的两个临时合成页面。先确认本机有可用的 `agent-browser` 和 Chromium，在仓库根目录执行下面的命令。将本次临时目录路径给第二个终端使用。

```sh
ui_run_dir=$(mktemp -d)
echo "$ui_run_dir"
PLATFORM_ENV_FILE=/dev/null python3 scripts/accept_foundation_extensions.py \
  --serve --state "$ui_run_dir/panels.json" --report "$ui_run_dir/foundation.json"
```

出现 `browserReady` 后，在第二个终端把 `ui_run_dir` 设为上一步输出的路径，再执行下列命令。浏览器报告和截图写入该目录。结束后在首个终端按 Ctrl-C，脚本会清理临时服务。

```sh
inventory_url=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["panels"]["sample_inventory"]["url"])' "$ui_run_dir/panels.json")
schedule_url=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["panels"]["sample_schedule"]["url"])' "$ui_run_dir/panels.json")
python3 scripts/accept_workbench_browser.py \
  --inventory-url "$inventory_url" --schedule-url "$schedule_url" \
  --report "$ui_run_dir/browser.json"
```

该脚本已有键盘、焦点、窄屏溢出、查询恢复、复制等检查。上表提出的四主题逐状态外观、微缩回弹、减少动态效果和具体业务判定，需在受影响页面另留证据。 [定向回归清单](../../resources/targeted-regression.json) · [浏览器验收脚本](../../scripts/accept_workbench_browser.py)

### 如何记录覆盖

以“页面 / 动作 / 对象作用域 / 出现条件”为一项，先列清改动入口，再点验。相同行模板可合并，但首次加载、动态插入、恢复查询、条件禁用和权限变化分别记录。同一动作有多个入口时，列出每个入口。覆盖结果同时记录“已触发的控件类型 / 适用类型”和“已验证的结果分支 / 适用分支”。无法构造的场景标记未执行，记录原因。要求全项目覆盖时，分母取本次版本盘点得到的清单。

| 记录示例（拟验收，未执行） | 预期证据 |
|---|---|
| 服务 A 开启，响应丢失，刷新后查询 | A 显示待确认，B 可操作。网络摘要记录原写入 1 次，后续查询使用同一标识，追加写入 0 次。查询取得可信状态后方可展示“已启动”。 |
| 另一对象 B 被拒绝，A 的旧响应迟到 | 错误留在 B 旁，A 的响应只更新 A。截图含对象和反馈，初次失败与后续复验分别保留。 |

验收记录至少包含版本、入口、主题与视口、触发方式、故障是否注入、实际状态与请求摘要、证据位置、通过 / 失败 / 未执行。证据中的标识可脱敏并保持可关联。交付时分别列出离线行为、真实浏览器中的合成操作、实际业务验收的范围与结论。只运行受影响的定向测试。
