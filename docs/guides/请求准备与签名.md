# 请求准备与签名

Core 能力名为 `prepared_requests`。需要此能力的 Pack 在 `platform_api.features` 中显式声明，再在自身 Adapter 中构造会话。现有不使用新参数的请求、TokenProvider、RequestAuthProvider、ResponseDecoder 与旧 `HttpTransport` 保持原调用方式。

## 生命周期与职责

新会话按“检查目标 → 获取本次身份 → 构造项目请求头 → 编码一次 → 冻结准备请求 → 签名追加头 → 校验最终请求头 → 取消检查 → 发送”执行。Core 不选择业务签名算法、查询排序、签名字段、商户凭据、金额或 ID 线型，也不读取其他 Pack 的配置。

`ApiSession` 新增三个可选参数：

| 参数 | Adapter 协议 | 职责 |
| --- | --- | --- |
| `request_encoder` | `encode(data, *, method, url) -> bytes` | 将显式提供的 JSON 值编码一次；金额等类型策略来自该 Pack 的请求契约 |
| `request_signer` | `sign(request) -> Mapping[str, str]` | 读取准备结果，只返回新增签名头；不能覆盖已有头 |
| `prepared_transport` | `request_prepared(request, *, timeout) -> (status, decoded_body)` | 接收同一冻结表示，原样消费正文；不再编码、不跳转、不自动重试 |

任意新参数、显式 `raw_body` 或 `data=JSON_NULL` 都启用准备路径。未提供编码器时使用 `JsonRequestEncoder`：普通 `json.dumps(..., allow_nan=False)` 的 UTF-8 表示，不将 Decimal 转 float 或 string。这个新路径拒绝非有限数；旧路径的 JSON 行为保持兼容。

`PreparedRequest` 的 `method`、`url`、`headers`、`body` 可读，另有 `path`、原始编码 `query` 属性。method 转为大写，空路径规范为 `/`，URL 必须事先编码且无 fragment、空白、控制字符或内嵌凭据；这些在签名前处理。headers 拷贝为只读映射，body 只允许不可变 bytes 或 None。默认 repr 隐藏 URL、headers 和 body。协议防止常规代码误改，不是执行不受信任 Pack 的安全沙箱。

`prepare_request(method, url, headers, *, data=None, raw_body=..., request_encoder=None, request_signer=None)` 可独立用于离线准备和契约检查，不会发送请求或获取身份。低层 `http()` 也支持同名准备参数；直接调用它时，调用者须确认目标和认证授权，基于会话的同源保护由 `ApiSession` 提供。

## 无正文、空正文与 null

| 调用 | 准备 body | 编码行为 |
| --- | --- | --- |
| `session.post(path, data=None, ...)` | `None`，无正文 | 不调用编码器 |
| `session.post(path, raw_body=None, ...)` | `None`，显式选择无正文准备路径 | 不调用编码器 |
| `session.post(path, raw_body=b"", ...)` | `b""`，空正文 | 不调用编码器 |
| `session.post(path, data=JSON_NULL, ...)` | 默认 `b"null"` | 向编码器传入 Python None，编码一次 |
| `session.post(path, data={...}, ...)` | 编码器返回的 bytes | 编码一次 |

`raw_body` 与非 None 的 `data` 互斥；raw bytes 从不再次 JSON 编码。自定义编码器必须返回 bytes，不能返回字符串、bytearray 或 None。无正文和空正文可能有相同摘要，是否在签名中区分正文存在性由业务协议决定。HTTP 标准传输可能为无正文的 POST 设置 `Content-Length: 0`；正文存在性首先是本地调用契约，不能仅凭这个头推断调用者意图。

## 最小 Adapter 示例

`examples/adapter_recipes/signing.py` 提供离线、无凭据访问的合成配方：`ExactJsonEncoder` 显式接受有限 Decimal 为 JSON number、拒绝 float，并保留 bool、整数与字符串；`SyntheticDigestSigner` 对 method、path、**原始 URL query**、正文存在性和摘要签名。它是演示协议，真实项目应复制到自身 Pack helpers 后按已确认协议修改，不能据此认定业务契约支持某种金额线型。

```python
from api_client import ApiSession, JSON_NULL
from packs.my_project.helpers.signing import ExactJsonEncoder, SyntheticDigestSigner

# key 从当前 Pack 的凭据来源获取；bootstrap 只注册，不读取真实凭据。
session = ApiSession(
    base=confirmed_base_url,
    request_auth=ProjectHeaders(),
    request_encoder=ExactJsonEncoder(),
    request_signer=SyntheticDigestSigner(key),
    response_decoder=ProjectResponseDecoder(),
)
status, body = session.post("/confirmed-path", {"label": "原文"}, with_token=False)
status, body = session.post("/confirmed-path", JSON_NULL, with_token=False)
```

示例使用 `with_token=False` 表示该操作依赖签名；同时需要 TokenProvider 的项目可使用原有 `default_user/token_provider/username/token` 参数，签名器能看到本次身份生成的头。请求编码策略与响应解码策略独立，不能把业务/DB Decimal 自动视为响应 JSON number。

## 查询与头策略

会话沿用原有 `params` URL 编码。Adapter 从准备结果读取实际 path/query；需要特殊查询编码的项目，可将已确认编码的 path/query 显式传入，避免再次提供相同 params。Core 不排序、去重或猜测参与签名字段。空格、加号、百分号及重复查询值的协议选择应由项目定向测试确认。

签名器返回的是新增头映射，已有头（名称不区分大小写）不得覆盖。签名所需的既有 Content-Type 等由 RequestAuthProvider 显式提供。HTTP 头名称在默认传输中会按 urllib 规则规范大小写；协议应按 HTTP 的大小写不敏感规则处理名称，不能依赖原字母大小写。urllib 会强制发送 `Connection: close`，因此 Core 在签名前将该头明确冻结为小写值 `close`，并拒绝 keep-alive 等其他取值；fake transport 接收同一个值，签名器也不能覆盖。传输可能补充其他标准 framing 头；如业务签名包含这些头，Adapter 必须在签名前显式给出正确值。Core 拒绝重复头、非法控制字符、Transfer-Encoding 以及与固定正文不一致的 Content-Length。

## 传输兼容与边界

旧 `transport.request(method, url, headers, data=Python对象, timeout=...)` 保持原格式。准备路径拒绝与旧 transport 混用，不能靠假传输测试通过后让默认网络重新编码。迁移测试 transport 时显式实现 `request_prepared`，例如：

```python
class RecordingTransport:
    def request_prepared(self, request, *, timeout=30):
        assert isinstance(request.body, bytes) or request.body is None
        # 仅在受控合成测试中检查正文；真实凭据和正文不得自动写入日志。
        return 200, {"ok": True}
```

注入 transport 与旧 fake 一样返回已解码结果，负责自己的响应解码；Core 不再次调用 ResponseDecoder。默认网络对成功和 HTTP 错误响应共用现有 ResponseDecoder，保留二进制与 parse-error 行为。

准备路径的默认传输禁用代理并拒绝全部重定向，包括同源跳转，不携带旧签名重放到新路径。没有自动重试或 401 自动刷新重放。签名、编码或最终头校验失败时不发请求；取消检查在准备前和最终 I/O 前执行。超时保持现有 transport-error 表示；连接失败不返回包含认证信息的驱动原文。未知写结果仍由 Pack 查询原单和处理恢复。

`ApiSession` 在跨源判定后才构造认证。默认跨源拒绝；显式 `allow_external=True` 时不调用 TokenProvider、认证头构造器、签名器或认证校验器，且拒绝自定义头。明确提供的 body 和编码器仍适用，因此调用者应仅发送已授权的数据。自定义 transport 是受信任 Adapter，必须自行遵守不重试、不转发凭据、不改正文和不跳转的协议。

## 定向验证与迁移

需要检查下载内容时，Pack 可声明 `bounded_attachment_response`，在一次调用中显式设置 `max_response_bytes` 为正整数。支持平台默认传输的传统请求与准备请求路径。调用继续返回 `(HTTP 状态码, 结果)`。成功的非 JSON 附件结果为 `AttachmentResponse`，可读取 `content` 字节及 `content_type`。未指定上限时沿用原有文件元信息与 JSON 返回方式。

```python
from hashlib import sha256
from api_client import AttachmentResponse

status, value = session.get("/confirmed-export", max_response_bytes=64 * 1024)
if status == 200 and isinstance(value, AttachmentResponse):
    evidence = {"size": len(value.content), "sha256": sha256(value.content).hexdigest()}
```

同一请求的上限适用于成功及错误响应。限额内的 JSON 仍经原解码器处理；超限返回原 HTTP 状态及 `_response_too_large`、`_parse_error` 标记，已知截断返回 `_response_incomplete`。文件原文只交给调用者。将大小、摘要等经项目选择的元信息写入历史或任务结果。使用自定义 transport 的 Pack 继续由自身 transport 管理响应和读取上限。

`tests/test_prepared_requests.py` 使用合成签名器、fake transport 和模拟默认网络，覆盖正文三态、Unicode、精确小数、大整数、查询特殊字符、冻结、失败不发、旧协议兼容、取消、解码、跨源与重定向边界。自有回环接入验收再核对服务端实际收到的 body 摘要与签名输入；这些均不代表真实业务验收。

```sh
PLATFORM_ENV_FILE=/dev/null PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_prepared_requests.py -v
```

升级先声明平台 feature 并通过当前 Pack 的定向测试。先迁移一条合成请求，再迁移获准的真实请求；保留项目白名单、身份一致性、金额线型、Mock 范围与结果信封，不把通用请求管线当成业务认证正确的证明。
