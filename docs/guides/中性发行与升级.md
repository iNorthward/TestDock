# 项目启动、中性发行与升级

## 项目启动

生成项目后，从该 Pack 的入口启动、查看状态和停止。三个动作都使用同一份配置与同一组进程归属检查。

```sh
./packs/sample_app/launch.sh start
./packs/sample_app/launch.sh status
./packs/sample_app/launch.sh stop
PLATFORM_ENV_FILE=.env.sample_app.review ./packs/sample_app/launch.sh status
```

项目入口默认使用 `.env.sample_app`，显式指定的环境文件应仍选择本 Pack。借用另一项目的配置会在操作进程前被拒绝。根目录的 `start.sh` 继续支持显式选择环境。新生成的入口属于 Pack，与项目说明、品牌和业务配置一起维护。

## 中性发行

维护中的平台源码用 `resources/platform-distribution-files.json` 登记确切的中性文件及 SHA-256。清单来自 Core 登记、中性工作台与启动文件、通用文档、定向回归和合成示例。导出逐文件核对摘要并检查最终平台目录。离线 demo 的清单来自 `examples/demo_pack/pack.json`，因此本机是否安装了 demo 不影响发行。

平台维护者审阅本次平台改动后刷新清单，并检查清单差异。该操作在维护中的中性源码执行。

```sh
python3 scripts/export_platform.py --seal-source
python3 scripts/export_platform.py --output /tmp/testdock-release
python3 scripts/check_neutral_distribution.py --root /tmp/testdock-release/platform --json
```

派生项目从一份已审阅的原始平台发行重组中性平台。导出器以原发行的 `distribution.json` 核验收到的字节，项目的根说明、规则、启动文件和品牌资源不会成为中性平台输入。所选本地 Pack 单独导出，并核对它所需的目标平台能力。

```sh
python3 scripts/export_platform.py --neutral-source /path/to/original/platform --pack sample_app --output /tmp/review-release
```

维护者信任并保留原发行及收据。SHA-256 用来检查内容一致性，发布来源仍由接入者确认。凭据、项目运行库和历史证据使用独立目录。

接收者把选定的 Pack 安装到中性平台后，先在本机创建忽略的 `.env.sample_app`，填写 `PLATFORM_PACKS=sample_app`。端口和数据路径可沿用 manifest 的项目默认值，接入凭据按本 Pack 的说明单独配置。

## 独立副本升级预检

```sh
python3 scripts/project_upgrade.py --current . --baseline /path/to/original/platform/distribution.json --target /path/to/target/platform --pack sample_app
```

预检在没有 Git 的目录也能运行。原始收据可以通过 `--baseline` 指定，也可使用当前副本保留的 `distribution.json`。目标目录使用其完整发行收据。报告按路径列出仅上游变化、仅本地变化、双方一致的改动和冲突，并给出新增、删除或修改。缺少原始收据时，差异来源标记为待核对。比较范围是收据与 Core 清单登记的平台文件。

报告同时核对所选 Pack 对目标 API 范围和能力的声明，并给出 Pack 自有目录及其声明的源码中显式引用变更平台模块的文件与行号。动态导入及运行行为由后续独立定向验收核实。预检只向标准输出写 JSON。兼容性拒绝返回退出码 1，缺少基准或有待核对项返回 2。确认差异后，继续按[升级门禁](../onboarding/AGENT_OPERATIONS.md)验证独立进程。
