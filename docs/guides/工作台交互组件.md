# 工作台交互组件

`assets/workbench-components.js` 提供全局 `PlatformWorkbench`，`assets/workbench-components.css` 提供局部反馈、受限表格横滚与窄屏详情样式。它们是可组合的小函数，不接管页面布局、业务状态或请求提交。原案例面板和工作区外壳继续使用既有入口；采用新组件是 Pack 的显式选择。

## 装载与安全

```html
<link rel="stylesheet" href="/assets/workbench-components.css">
<script src="/assets/execution-client.js" defer></script>
<script src="/assets/workbench-components.js" defer></script>
<script src="/pack-assets/my-page.js" defer></script>
```

平台服务端会在页面 head 注入 `security-client.js`，应用继续使用已受保护的 `window.fetch`，不要重新获取、存储或拼装会话 Token。`execution-client.js` 继续管理 POST 的 requestId、未知结果与终态关联。新组件不创建另一套后台任务、会话或业务幂等机制，也不自动重发业务写请求。

组件不会猜测字段语义。Pack 负责接口、字段白名单、明确的只读 loader、金额单位和线型、详情投影、列表唯一键与分页协议。浏览器存储不应含密钥、Token、认证头或私密响应；白名单选择是 Pack 的责任，组件不会根据字段名自动认定安全。

## 局部反馈

```javascript
const notice = PlatformWorkbench.feedback(document.querySelector('#near-button-status'));
notice.set('正在读取原记录…');
notice.set('读取失败，保留已确认结果。', {kind: 'warning'});
```

区域使用 `role=status`、`aria-live=polite` 和文本节点。`kind` 为 `info / success / warning / error`。业务文案与结果结论由页面提供；组件不会把任务结束、案例通过与业务成功混为一谈。

## 原任务保存与恢复查询

```javascript
let storage;
try { storage = window.sessionStorage; } catch (_) {}
const task = PlatformWorkbench.createTaskController({
  pack: 'sample', page: 'records', scope: 'explicit-owner', storage,
  fetcher: window.fetch, execution: window.PLATFORMExecution,
  onProgress: job => notice.set('原任务：' + job.status),
  onResult: (result, job) => renderProjectedResult(result, job.status),
  onState: (state, identity) => renderTaskControls(state, identity),
  onNotice: message => notice.set(message, {kind: 'warning'}),
});
// 仅在页面明确提交并拿到 executionId 后记录；组件不负责提交。
task.remember({executionId: originalExecutionId});
await task.watch();
// 新页面：恢复本地身份本身不发送任何请求。用户恢复后只查询原任务。
const recovered = task.restore();
if (recovered) resumeButton.onclick = () => task.watch().catch(showQueryFailure);
```

`remember / restore / snapshot` 只保留原 `executionId` 和组件记录版本，按 Pack、页面和作用域分别保存；不保存请求正文、任意上下文或结果。原任务尚未确认终态时，`remember` 拒绝用其他标识覆盖它。`watch()` 调用既有 `PLATFORMExecution.pollJob`，并发调用共享同一轮查询。查询失败和等待超时保留原标识，状态为 `unavailable`；恢复时仍查询该 executionId。

确认终态后才调用 fetch 上已有的 `completeExecution(executionId)`，清除组件恢复记录并发出 `terminal`。任务已结束而结果已过期或缺少证据时给出 `ok:null,status:incomplete`。其他结果原样交给 Pack，不因任务 `done` 改成业务成功。`pollOptions` 可显式配置既有轮询器的间隔和超时；不会新增写入重试策略。

首个执行响应未收到时，可用共享执行客户端从原请求号恢复。自动生成请求号的 JSON POST 可提供 `onExecutionRequest(requestId)`，在发出请求前保存最小身份。用户恢复查询时调用 `PLATFORMExecution.lookupReceipt(window.fetch, requestId, kind)`。返回 `null` 时保留待核验状态。查到回执可按其中的 `id` 查询任务，确认终态后以 `completeExecution(id, requestId)` 清理旧关联。自定义任务的 kind 由其 Pack 的提交入口提供。

## 详情弹框与投影

```javascript
const details = PlatformWorkbench.createDetailsDialog({
  dialog, body: document.body, status: detailStatus, content: detailContent,
  project: value => '公开编号：' + value.publicReference + '\n状态：' + value.visibleStatus,
});
await details.open(triggerButton, {
  key: ownerScope + ':' + recordReference,
  initial: confirmedResult,
  load: () => readProjectedDetail(recordReference), // Pack 明确保证只读
});
retryButton.onclick = details.retry;
closeButton.onclick = details.close;
```

`key` 必须是非空且含记录作用域的文本。切到其他 key 会清空旧记录；相同 key 重读失败保留已确认结果，并在独立区域显示读取失败和重试提示。只有 `project` 明确选择并返回的文本会进入弹框，不默认展开整个服务器对象；投影不能返回 HTML。`setResult(value)` 可更新当前确认结果，`snapshot()` 可读取状态。

原生 `<dialog>` 配合组件支持 ESC、Tab/Shift+Tab 焦点循环、背景滚动锁定及关闭回到触发按钮；关闭后迟到的读取结果失效。弹框须设置 `aria-labelledby`，放置可见关闭和重试按钮，并使用 `wb-dialog` 样式。表格超宽应在 `wb-table-scroll` 内横滚。

## 白名单表单保存

```javascript
const form = PlatformWorkbench.createFormContext({
  pack: 'sample', page: 'records', scope: chosenOwner, version: 1, storage,
  fields: {description: descriptionInput, layout: layoutSelect},
  onNotice: message => notice.set(message, {kind: 'warning'}),
});
const restored = form.restore();
form.setPending(['layout']); // 显式声明选项尚未装载
form.bind();                 // 文本 input 即时保存；select 在 change 保存
const options = await readOptions();
renderOptions(options, restored.layout);
form.setPending([]);        // 明确空响应与尚未加载分开
form.save();
// 身份切换时清空旧字段，再恢复新作用域；重新声明 pending 并载入选项。
const next = form.setScope(nextOwner);
```

只保存 `fields` 中的文本 value。选项尚未装载且当前值为空时，`save` 保留该作用域之前的选择；加载完成后明确空值可正常保存。页面须使用 `restore()` 返回值在异步选项完成后恢复选择，并在作用域切换后丢弃旧选项响应。

存储 key 隔离 Pack / 页面 / 作用域。`version` 为正整数；不兼容记录不自动迁移，通过 `onNotice` 提示重新选择。存储被禁用、损坏或配额失败时页面仍可操作，并提示刷新无法恢复。调用 `dispose()` 解除事件监听；多次 `bind()` 不会叠加监听。

## 只读列表与不透明游标

```javascript
const list = PlatformWorkbench.createReadonlyList({
  scope: () => owner + ':' + ownerGeneration,
  load: ({filters, limit, cursor, scope, signal}) => readList({filters, limit, cursor, scope, signal}),
  rowsOf: response => response.entries,
  cursorOf: response => response.continuation,
  keyOf: row => row.explicitUniqueReference,
  onChange: state => renderList(state),
});
await list.query({filters: {search: searchInput.value}, limit: pageSize.value});
await list.query({filters: {search: searchInput.value}, limit: pageSize.value, append: true});
```

组件只接受 Pack 显式给出的 loader、响应投影、文本唯一键和游标投影，不推断 API、字段名、排序、ID 类型或分页协议。它保留服务端顺序，追加时按唯一键去重；游标原样交给下次 loader，不转整数。筛选、条数或 scope 变化时，即使 `append:true` 也从首屏读取并清空旧行。

每次查询使旧查询失效，并中止旧读取信号；即使 loader 不支持中止，旧响应仍不能覆盖新选择。scope 应包含身份切换代数，避免从 A 切到 B 再回 A 时旧 A 查询重新生效。`invalidate()` 主动作废当前查询；`snapshot()` 返回当前行、游标、加载状态和错误。filters 应为可 JSON 序列化的显式普通数据，筛选对象字段顺序变化可能导致安全的首屏重置。

## 精确文本、时间与复制

```javascript
PlatformWorkbench.presentExact(valueNode, verifiedText, {trimFractionZeros: true});
timeNode.textContent = PlatformWorkbench.formatTime(originalISO, {timeZone: 'UTC'});
timeNode.title = originalISO;
copyButton.onclick = () => PlatformWorkbench.copyExact(verifiedText, {status: nearbyCopyStatus});
```

`formatExactText / presentExact` 仅接受字符串或缺失值；Number 会明确报错。`trimFractionZeros` 只修改普通十进制字符串的显示尾零，不舍入、不改原值，原值写入 title；前导零、长整数、指数文本原样保留。复制使用原文本并就近报告成功、权限拒绝或浏览器不支持，旧复制响应不会覆盖新反馈。

这是显示边界，不能恢复普通 `response.json()` 已把 JSON number 解析为 Number 后丢失的精度。Pack 必须依据各自请求/响应契约提供已核实的精确文本投影或无损解码结果，不能把显示函数当作 wire 校验器，也不能为方便显示擅自改变接口线型。

`formatTime` 必须显式给出合法 IANA `timeZone`；只格式化带 Z 或偏移量的 ISO 时间。时区缺失、非法日期和未知值保留原表示，不猜浏览器本地时区或补零。金额单位、有效精度、舍入及时间业务含义继续归 Pack。

## 两种合成接入样例与定向验证

仓库根目录运行：

```sh
python3 -m http.server 8819 --bind 127.0.0.1 --directory .
```

访问 `http://127.0.0.1:8819/examples/workbench_components/inventory.html` 或 `schedule.html`。两页共用同一组件与 `demo.js`，但使用不同 Pack ID、字段白名单、页面布局、作用域和显式时区。所有任务/列表均为浏览器内 synthetic transport，页面不发送业务接口请求。静态服务器不具备平台会话接口；实际接入 Pack 时继续使用平台已保护的 fetch。

也可把各 HTML 分别放入两个临时 Pack 的 `panel_html`，把 `demo.js / demo.css` 复制到各自 assets，并把页面 `./demo.js / ./demo.css` 改成 `/pack-assets/demo.js / /pack-assets/demo.css`。组件资产仍使用 `/assets/`。每个进程只加载一个 Pack；两次浏览器验收需要独立端口、数据根和环境文件。

```sh
node --test tests/test_workbench_components.js tests/test_execution_client.js tests/test_security_client.js
```

新测试覆盖未知任务保留、终态/过期结果、无写入恢复、存储隔离/失败、即时表单和加载竞态、列表乱序/不透明游标/重置、详情投影/失败保留/焦点、长文本精度/时区和复制拒绝。Node 的简化 DOM 不代表浏览器验收；交付时另检查两种页面的实际刷新恢复、身份切换、键盘、390px 横向边界与就近反馈。

可重复浏览器验收器为 `scripts/accept_workbench_browser.py`。它额外依赖本机可用的 `agent-browser` CLI 和 Chromium，仅在显式验收时使用，不是平台运行依赖。先用 `scripts/accept_foundation_extensions.py --serve --state /tmp/foundation-panels.json --report /tmp/foundation-extensions.json` 启动两个临时 Pack，再把 state 文件内的两个 URL 传给浏览器验收器的 `--inventory-url`、`--schedule-url`，并指定 `--report /tmp/workbench-browser.json`。结束后在服务命令处 Ctrl-C，清理临时服务与数据。

浏览器脚本只接受本机 HTTP 回环 URL，使用独立命名会话，检查真实输入、刷新、键盘、焦点和布局。任务传输、查询断开及剪贴板拒绝均为显式合成故障；复制成功核对实际浏览器写入 API 的完整参数和成功结果，不声称已读回操作系统剪贴板。报告与截图应单独保留，不作为真实业务验收。

合成通过只证明平台机制和接入方式，不证明任何真实业务通过；TestDock 新增组件也不表示其他独立发行副本已完成升级。
