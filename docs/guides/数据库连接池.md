# 数据库连接池

统一入口为 `test-platform/common/db_conn.py` 的 `db()`。默认使用 SQLAlchemy 2.0.54 QueuePool 管理 PyMySQL，不引入 ORM；连接目标、凭据和默认值来自当前 Pack 的 `PLATFORM_DB_*` 配置。SQLite 历史库不使用此池。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| PLATFORM_DB_POOL_ENABLED | 1 | 0 回退短连接并关闭已有池，只允许 0/1 |
| PLATFORM_DB_POOL_SIZE | 5 | 每组保留的连接数，正整数 |
| PLATFORM_DB_POOL_MAX_OVERFLOW | 5 | 额外并发连接数，非负整数 |
| PLATFORM_DB_POOL_TIMEOUT | 5 | 池满等待秒数，正整数 |
| PLATFORM_DB_POOL_RECYCLE | 1800 | 借出时回收超过该年龄的连接，正整数 |

每组上限 size + overflow，不超过 100；每进程最多 16 组数据库/超时配置。连接懒创建，不在启动时建满。多进程部署须累计容量。主机、凭据或池选项改变会替换对应池；旧池空闲连接关闭，旧租约归还时关闭。

```python
from db_conn import db

with db() as conn:
    with conn.cursor() as cursor:
        cursor.execute("SELECT 1 AS value")
        row = cursor.fetchone()
```

`conn.close()` 归还连接，重复关闭无副作用。归还时先向服务端发送 COM_RESET_CONNECTION（MySQL ≥ 5.7.3、MariaDB ≥ 10.2.4），清空用户变量、临时表、GET_LOCK 锁、会话变量、预处理语句和未提交事务，再 rollback；借出时探活并恢复 autocommit、数据库、utf8mb4 和项目时区（由 `timezone_config.mysql_session_time_zone()` 从 `Asia/Shanghai` 推导，当前为 +08:00）。保留 DictCursor、Decimal 和整数原始类型。业务 SQL 失败直接上抛，不自动重放。

池满等待超过 PLATFORM_DB_POOL_TIMEOUT 抛出 `db_conn.DatabasePoolExhausted`（带 `[incomplete]`，同时是 SQLAlchemy TimeoutError 子类），案例执行器将其记为 incomplete 而不是 failed；它与数据库连接/读写超时独立。超时只说明本次未取得连接，不代表案例此前没有其他操作，重试前须核验状态。

租约应由单线程独占，cursor 在归还前关闭。cursor 操作、属性读写、迭代和预先保存的方法均校验原租约；归还、invalidate 或跨进程使用会拒绝。cursor.connection 返回租约。fork 子进程创建新池并拒绝父进程租约。

会话清理是 fail-closed 的：驱动缺少该命令、服务端拒绝（如不支持的代理/旧版本）或网络失败时，SQLAlchemy 记录错误并淘汰该物理连接，下一次借出新建连接，不会把上一案例的会话状态交给下一案例。此时池退化为每次新建连接，日志中会出现 `Exception during reset`，应升级服务端或设置 PLATFORM_DB_POOL_ENABLED=0。案例无需再手动 invalidate；需要立刻丢弃连接时仍可调用 `conn.invalidate()`。连接池减少重复建连成本，不加速 SQL 本身。

PyMySQL 与 SQLAlchemy 均为 `requirements.txt` 声明的必需依赖，`scripts/check_env.py` 在数据库分组按包名（python:PyMySQL / python:SQLAlchemy）报告缺项。缺 PyMySQL 或启用池但缺 SQLAlchemy 会返回带 incomplete 标识的异常；短连接模式不要求 SQLAlchemy。未安装依赖时 `tests/test_db_pool.py` 整组跳过；真实库会话隔离测试 `tests/test_db_pool_mysql.py` 需设置 PLATFORM_TEST_MYSQL_* 才运行。运行中的服务重启后加载代码变更。
