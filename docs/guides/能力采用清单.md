# 能力采用清单与证据接续

能力清单描述当前 Pack 如何采用底座，以及哪一范围经过显式验证。配置存在、源码引用、装载成功、mock 通过分别说明不同事实。清单不自动登录、联网、建立账号或执行案例；`doctor` 仍只运行显式指定的离线 mock。

所有入口使用 `platform_capabilities.adoption_report()`：`project_doctor.py` 的 `capabilityAdoption`、`project_tasks.py status` 的同名字段及 `/api/platform` 展示相同结构。`basis=saved_manifest` 表示磁盘声明；正在运行的进程是否已重启并装载该声明，应另外核对运行快照。平台优化不会自动升级其他独立发行。

## 声明接入选择

在所属 Pack 的 `pack.json` 添加：

```json
{
  "capability_adoption": {
    "version": 1,
    "items": {
      "http": {
        "mode": "core",
        "required": true,
        "required_scope": "synthetic",
        "sources": ["adapter:packs/my_app/integration.py", "config:SERVICE_URL"],
        "reason": "复用 ApiSession，编码与认证策略由 Adapter 注册"
      },
      "resource_pool": {
        "required": false,
        "reason": "本项目由调用参数提供身份，无共享样本需求"
      }
    }
  }
}
```

支持的能力 ID 为 `http`、`resource_pool`、`database_pool`、`background_tasks`、`request_deduplication`、`resource_mutex`、`ui_components`、`evidence_handoff`、`diagnostics`。只声明实际接入选择，不从能力名称推断业务语义。

| 字段 | 契约 |
| --- | --- |
| `mode` | `core` 复用底座；`pack` 专用实现；`disabled` 主动关闭；`unconfigured` 尚未配置；`unavailable` 当前不可用 |
| `required` | 必须是 JSON boolean；仅由 Pack 决定是否为交付必需 |
| `required_scope` | 可选，精确匹配 `synthetic`、`mock`、`real_readonly`、`manual_review`；没有隐式等级替代 |
| `sources` | 公共引用数组：`manifest:字段.子字段`、`config:环境键名`、`adapter:packs/<id>/源码文件`；不含配置值 |
| `reason` | 公开的单行说明；专用实现、关闭、尚未配置或不可用必须说明原因；不得写凭据或业务资源原文 |

`resource_pool` 与 `diagnostics` 的方式分别从原有 `resource_pool.enabled` / 旧 `identity_requirements`、`diagnostic_capabilities` 派生，新增项只补必需性、原因和证据范围。可以重复写相符的 `mode`，冲突会拒绝；不能维护第二份启用真值。其他能力的 `core` / `pack` 必须提供显式来源。来源表示声明出处，不证明运行时复用或容量已经验证。

旧 Pack 不必立即补齐。缺失的新声明显示 `declared=false`、`needsMigration=true`、必需性未知；已有资源/诊断开关仍可显示，但验证为 `not_run`。旧 Pack 可正常装载。迁移时逐项补实际选择与原因，再执行所需范围的验收；不要把 `platform_api.features` 当成采用证明。

未声明新能力且没有新收据的旧 Pack，仍遵守原 registry 的显式源码归属规则；不会因为仓内旧 Adapter 或共享面板不在 `packs/<id>/` 内而被新的证据绑定阻断。显式采用新能力后，相关 Adapter 来源须满足上述所属 Pack 路径规则，再捕获验证上下文与登记证据；不能把旧报告直接贴成新版本已验证。

## 显式记录证据

原来的六个接续任务保持不变。新增收据位于同一份 `data/<pack>/onboarding-tasks.json` 顶层 `capabilityEvidence`，不新建任务数据库、不改变 `real_readonly` 为业务写验收。投影结果不作为第二份状态存入任务文件。

先捕获验证前上下文，再执行所属 Pack 的定向检查：

```sh
mkdir -p artifacts/my_app
PYTHONDONTWRITEBYTECODE=1 python3 scripts/project_tasks.py --pack my_app capability-context --capability http > artifacts/my_app/http-context.json
PLATFORM_PACKS=my_app PLATFORM_ENV_FILE=/dev/null PYTHONDONTWRITEBYTECODE=1 python3 scripts/targeted_regression.py --group my_app.adapter --report artifacts/my_app/adapter-regression.json
```

只有该组实际包含所需 HTTP Adapter 断言、使用合成数据并通过时，才可形成相应 `synthetic` 事实。通用回归绿色不能替每个能力生成“已验证”。以下配方复用刚才的报告；它只组合证据，不执行额外案例：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 - <<'PY'
import hashlib, json, time
from pathlib import Path
root = Path.cwd()
context = json.loads((root / 'artifacts/my_app/http-context.json').read_text())
source_path = root / 'artifacts/my_app/adapter-regression.json'
source_bytes = source_path.read_bytes()
source = json.loads(source_bytes)
assert source['ok'] is True
assert type(source['testsRun']) is int and source['testsRun'] > 0
assert source['groups'] == ['my_app.adapter']
fact = {
    'pack': 'my_app', 'capability': 'http', 'ok': True, 'status': 'passed',
    'scope': 'synthetic', 'verifiedAt': int(time.time()),
    'realBusinessVerified': False, 'binding': context['binding'],
    'evidenceRefs': [{'path': 'artifacts/my_app/adapter-regression.json',
                      'sha256': hashlib.sha256(source_bytes).hexdigest()}],
}
(root / 'artifacts/my_app/http-capability.json').write_text(
    json.dumps(fact, ensure_ascii=False, indent=2) + '\n')
PY
python3 scripts/project_tasks.py --pack my_app record-capability --capability http --evidence artifacts/my_app/http-capability.json
python3 scripts/project_tasks.py --pack my_app status
```

报告也可以由执行器直接产生相同公共字段，不要求使用上述配方。断言失败记录 `status=failed, ok=false`；未完成与未执行分别使用 `incomplete` / `not_run`，两者 `ok=null`。`verifiedAt` 为正整数 Unix 秒；`manual_review` 表示人工审阅，不能描述成运行时验证。新证据及被引用报告只允许位于 `artifacts/<pack>/`，不跟随其他项目或目录符号链接。

每份收据绑定报告 SHA-256、验证前的声明摘要、平台 API 版本、Core 归属清单及共享 JS/CSS 的汇总指纹、适用 Adapter 源码指纹。Adapter 包括声明的 `adapter_files`、条目 `adapter:` 来源、bootstrap、面板/目录扩展、面板 HTML 与 Pack 面板服务。清单不遍历业务数据或环境文件。依赖 helper 必须显式登记到 `adapter_files` 或 `sources`，不能凭 import 推断依赖闭包。证据引用仅保存路径和摘要，不复制报告正文。

报告或引用报告修改/删除、声明变化、平台版本或同版本 Core/UI 变更、已登记 Adapter 改动/删除都会使旧事实 `stale`。`record-capability` 要求输入报告的 `binding` 仍等于当前上下文，拒绝把旧结果重新贴到新代码上。Core 或 Adapter 已缺失时不得登记通过。重新执行相关范围并登记新报告，不能只更新旧报告的绑定字段。

## 真实只读范围保持原授权边界

`real_readonly` 不能通过一个自称真实通过的能力报告独立开启。必须先按 [操作手册](../onboarding/AGENT_OPERATIONS.md) 完成原有 `scope` 与 `real_readonly` 任务，保留当前 Pack 的授权和真实报告，两份证据均需位于 `artifacts/<pack>/`。旧路径中的证据可在授权范围内复制到该目录并重新登记；这不改变或扩大原授权。

能力报告另外要求 `realBusinessVerified=true`、实际非空唯一 `caseIds`、`scopeEvidenceSha256`。后者取验证前 `project_tasks.py status` 中 `scope` 任务的 `evidenceSha256`。实际案例必须同时被当前授权范围和已登记真实报告覆盖。系统复核两份原报告、摘要及真实任务绑定的授权摘要；报告变化、删除、撤销或替换授权后，该能力事实失效。`required_scope=real_readonly` 不能由 mock、合成测试或人工审阅满足。

采用清单的顶层 `realBusinessVerified` 始终为 false，防止单项事实变成整项目业务验收；查看具体条目的 `verification.scope`、授权摘要与案例覆盖，整项目真实验收仍看原接续任务。本文没有真实业务执行命令，也没有业务写验收入口。

## 读取结论

| 情况 | 采用清单结论 |
| --- | --- |
| 可选能力主动关闭且理由齐全 | `ready`，验证仍可为 `not_run` |
| 新声明未补齐的旧 Pack | 保持兼容，显示迁移提示与缺失项 |
| 必需能力未接入、证据缺失/失效/未完成、范围不符 | `incomplete, ok=null` |
| 声明与既有开关冲突、实际验证失败、证据状态非法 | `failed, ok=false` 或明确拒绝该非法输入 |
| 必需能力的当前证据已通过且范围相符 | `ready`；只证明该证据范围 |

条目的 `status` 表示必需条件是否满足，`verification.status` 表示证据事实；人工审阅通过但未达到要求的合成验证范围时，前者为 `incomplete`，后者仍保留原始 `passed/manual_review`。可选项失效仍显示 `stale`，不能把整体 `ready` 写成所有能力均已验证。交付同时报告未执行范围和迁移提示，不输出私密配置值、密码、Token、密钥或原始业务身份。
